# 단계별 따라 하기 교안 (step-lesson-builder)

화면을 보며 그대로 따라 하면 누구나 끝까지 갈 수 있는 **웹 교안 1개 + 공유 링크**를 만든다.
대한변리사회 회원서비스실 Apps Script 교안(https://aismartworkhub.github.io/KPAA/appscript/)이 완성 기준이다 —
사용자가 "이 스타일로 앞으로도"라고 요청해 만든 스킬이므로, 구성·말투·화면 표현을 그 교안과 같게 맞춘다.

## 왜 이 형식인가
수강생은 대개 비개발자이고, 강의 중에는 강사 화면과 자기 화면을 번갈아 본다. 그래서
- 한 단계에 **한 동작 묶음**만 두고, 왼쪽 글의 번호와 오른쪽 그림의 빨간 번호를 **같은 숫자**로 맞춘다 → 눈이 그림↔글을 오가도 길을 잃지 않는다.
- "성공하면 이렇게 보인다"를 매 단계 둔다 → 혼자서 맞게 했는지 판단할 수 있다.
- "막히면"을 매 단계 둔다 → 강사에게 묻기 전에 스스로 푼다.
- 코드·프롬프트는 복사 버튼으로 → 오타가 사라진다.
- 휴대폰에서는 복습용으로 읽기 좋게 → 그림은 화면 폭에 맞게 줄이고, 탭하면 크게.

## 작업 순서

### 1. 기획 (먼저 짧게 정리해 사용자에게 보여주기)
대화·회의록·요청 메일에서 다음을 뽑는다. 빠진 것만 묻고, 답이 없으면 합리적 기본값을 적용한 뒤 보고서에 가정으로 밝힌다.
- 대상(직무·디지털 숙련도), 회차·일시·회차당 시간, 최종 결과물("오늘 만드는 것" 3~4개)
- 실습 도구와 계정 종류(예: 회사 Google Workspace / 개인 Gmail → 권한 화면·한도가 달라짐)
- 실습 데이터: **실제 개인정보는 쓰지 않는다.** 실제 파일의 특징(열 이름, 제목행, 공백 등)만 살린 가상 데이터를 만든다.
- 모듈 구성: 0 준비 → 1 가장 작은 성공(10~20분 안에 "됐다!") → 2~ 실제 업무 → 마지막 AI에게 요청·수정하는 법 → 부록
기획안은 표로 보여주되, 사용자가 "바로 만들어"라고 하면 기본값으로 진행한다.

### 2. 실습 자산 만들기와 검증
- 코드·템플릿·데이터 파일을 교안 폴더의 `code/`, `practice/`에 둔다. 교안의 코드 상자는 `code_block(path=...)`로 **실제 파일을 그대로** 넣는다(교안과 파일이 어긋나지 않게).
- 실행 가능한 것은 실제로 돌려 본다. 외부 서비스(구글 등)를 쓸 수 없으면 모의 환경을 만들어 핵심 로직을 시험한다(예: Apps Script → Node `vm`으로 SpreadsheetApp 흉내). 검증 못 한 부분은 끝에 정직하게 알린다.

### 3. 교안 작성
`assets/lessonkit.py`(부품)와 `assets/example_build.py`(전체 예시)를 쓴다. **예시를 복사해 내용만 바꾸는 것이 가장 빠르다.**
```bash
mkdir -p <교안폴더>/src && cp <스킬>/assets/{lessonkit.py,lesson.css,lesson_runtime.js} <교안폴더>/src/
cp <스킬>/assets/example_build.py <교안폴더>/src/build.py   # sys.path 경로만 확인
python3 <교안폴더>/src/build.py <교안폴더>               # → <교안폴더>/index.html
```
- 단계 쓰는 법, 말투, 그림 그리는 법, 품질 기준 → `references/style-guide.md` (작성 전에 읽는다)
- 부품 목록과 사용 예(모형 화면: 구글 시트, 코드 편집기, 구글 권한 화면, 메일, AI 대화, 범용 앱 창, 메뉴·드롭다운·확인창·사이드패널) → `references/components.md`
- 실습 탭에는 `wrap(..., pc_note=...)`로 휴대폰에서만 보이는 "실습은 PC에서" 안내를 넣는다(편집 작업이 있는 교안일 때).
- 부록에는 자주 보는 오류, 되돌리기, 한도·주의사항, 개인정보 체크리스트, `shot_list_section()`(실제 캡처 교체 목록)을 넣는다.

### 4. 점검 (반드시 실행)
```bash
node <스킬>/scripts/check_lesson.mjs <교안폴더> <스크린샷폴더>   # Playwright 필요
```
PC 1280px와 휴대폰 390·360px에서 모든 탭을 열어 가로 넘침·잘린 글자·스크립트 오류·복사 버튼·그림 탭 확대·촬영 목록을 확인한다.
"문제 없음"이 나와도 스크린샷 몇 장(PC 실습 탭, 휴대폰 첫 실습 탭, 확대 화면)을 직접 열어 **번호가 글과 그림에서 일치하는지, 드롭다운이 잘리지 않았는지** 눈으로 본다.

### 5. 미리보기 이미지(카카오톡·SNS)
`assets/og_template.html`을 교안 폴더로 복사해 {{…}}를 채우고 오른쪽 카드를 주제에 맞게 바꾼 뒤:
```bash
node <스킬>/scripts/make_og.mjs <교안폴더>/src/og.html <교안폴더>/og_image.jpg
```
렌더링 결과를 직접 보고 제목이 어색하게 끊기면 글자 크기를 줄여 다시 만든다. `build(..., site_url=배포주소/, og_image="og_image.jpg")`로 메타 태그를 넣는다(이미지 주소는 반드시 절대경로).

### 6. 배포와 공유 링크
사용자가 링크를 원하면 끝까지 해서 **바로 공유할 수 있는 주소**를 건넨다. 절차·주의점 → `references/deploy.md`
(GitHub Pages 배포 확인, 카카오톡 미리보기 캐시 초기화 안내, 접속 확인 못 한 부분은 솔직히 알리기).

## 마무리 보고
- 공유 링크(있으면)와 파일 위치
- 탭별 구성 표(탭 / 내용 / 회차)
- 검증한 것 / 검증 못 한 것 (예: 실제 서비스에서 실행해 보지 못함 → 강의 전 1회 리허설 권장)
- 적용한 가정(실습 데이터, 시간 배분, 계정 종류 등)
- 실제 캡처로 바꾸는 법(부록 캡처 목록 → `shots/<ID>.png`)
