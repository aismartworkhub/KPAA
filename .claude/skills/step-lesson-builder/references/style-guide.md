# 교안 작성 스타일 가이드

## 목차
1. 페이지 구성 2. 단계 카드 쓰는 법 3. 말투와 표기 4. 모형 화면 그리는 법 5. 휴대폰·복습 6. 품질 체크리스트

## 1. 페이지(탭) 구성
| 탭 | 내용 |
|---|---|
| 홈 | `hero`(기관·과정 / 제목 2줄 / 한 줄 약속) → "오늘 만드는 것" `cards` 3~4개 → "진행 순서" `flow` → 회차 `table`(회차·일시·내용·준비물) → "꼭 지킬 원칙 3가지" `box` 3개 → 실습 파일 `downloads` → 모형 화면 안내 한 줄 |
| 0 준비 | 실습 파일 가져오기, 도구 열기 (10분 안쪽) |
| 1 첫 성공 | 가장 작은 기능 하나로 "붙여넣기 → 저장 → 실행 → (권한) → 확인" 한 바퀴. 끝에 "여기까지 배운 것" ok 박스 |
| 2~N 업무 | 실제 업무 흐름 그대로. 탭 맨 위에 `flow`로 전체 흐름 → 단계들 → 마지막에 "실제 업무에 적용하기" |
| AI 활용 | ✅ 줘도 되는 것 / ⛔ 주면 안 되는 것 / 💡 요령 박스 → 새 기능 요청·오류 고치기·기존 것 수정 프롬프트 카드 |
| 부록 | 권한·경고 화면 해설, 자주 보는 오류(문구·원인·해결), 실행 기록 보는 곳, 되돌리기, 한도, 개인정보 체크리스트, 캡처 목록 |

회차가 여러 번이면 홈 표에 회차별 탭 범위를 적고, 각 탭 제목 옆 small에 "2차 교육 · 약 40분"처럼 표시한다.

## 2. 단계 카드 쓰는 법 (`step`)
- **번호**: "모듈-순번"(1-3). 한 단계 = 화면 1~2개 안에서 끝나는 동작 묶음. 따라 하기 항목은 2~6개.
- **goal(🎯)**: 이 단계로 얻는 것 한 문장. "~합니다".
- **todo**: 명령형 짧은 문장. 화면 이름은 `ui('정확한 메뉴명')`, 키는 `kbd('Ctrl','V')`. 한 항목 = 한 동작.
  - 좋음: `메뉴 {ui('파일')} → {ui('가져오기')}` / 나쁨: "파일 메뉴에서 가져오기를 찾아 클릭한 다음 업로드를 선택하세요"
- **그림 번호 = todo 번호**: todo 3번이 "실행 클릭"이면 그림의 실행 버튼에 `mk(...,3)`. 그림에 없는 동작(키보드 등)은 번호를 건너뛰어도 된다.
- **ok(✅ 성공하면)**: 화면에 무엇이 보이면 성공인지 구체적으로. ("새 탭에 코드 편집기가 열립니다", "[발송상태]에 발송완료")
- **stuck(⚠ 막히면)**: 가장 흔한 실패 1~2개와 해결. 길면 부록으로 링크.
- **extra**: 코드 상자, 프롬프트 카드, 이유 설명(`box('info','왜 묻나요?',...)`), 주의(`box('warn',...)`), 금지(`box('no',...)`).
- 위험한 동작(실제 발송·삭제)은 **시험 → 확인 → 실제** 순서를 단계로 분리한다.

## 3. 말투와 표기
- 존댓말, 짧은 문장, 전문용어 최소화(쓰면 바로 풀이). "코드를 다 읽을 필요는 없습니다"처럼 안심시키는 문장을 적절히.
- 화면 속 이름은 실제 한국어 화면 그대로(예: 구글 시트 메뉴 "확장 프로그램", Apps Script "▷ 실행", 권한 "고급").
  바뀔 수 있는 문구는 "예전 화면은 허용"처럼 대안을 함께 적는다.
- 날짜 `11. 4.(수) 15:00`, 숫자는 천 단위 콤마.
- 실제 자료를 분석해 얻은 수치를 인용할 때는 **집계값만**(개인 식별 정보 금지).

## 4. 모형 화면 그리는 법 (`fig`)
- 실제 화면을 단순화한 모형. 메뉴 이름·위치·순서는 실제와 같게, 데이터는 실습 데이터 일부(5~7행).
- 화면 하나에 빨간 번호 1~4개. **번호는 실제로 누르거나 입력하는 곳에만** 단다. 그 결과로 바뀐 부분은 번호 대신 그림 설명(캡션)이나 "✅ 성공하면"으로 알려준다.
- 메뉴를 펼친 장면은 `dd_for=(메뉴이름, dropdown(...))`로 그 메뉴 바로 아래에 붙인다(고정 좌표 금지 — 좁은 화면에서 잘림).
  메뉴줄 오른쪽 끝 메뉴는 `align='right'`.
- 확인창은 `overlay=dialog(...)`, 오른쪽 패널은 `overlay=sidebar(...)`.
- 그림 ID(`m<모듈>-<순번>`)는 교안 전체에서 고유. 실제 캡처 파일명이 된다.
- 경고·권한 화면처럼 처음 보면 겁나는 화면은 **반드시** 그림으로 미리 보여주고 "정상"이라고 설명한다.
- 새 앱이 필요하면 `app_window(title, body_html, menus=...)`에 `grid`, `gbtn`, `.minput`, `.mbtn` 등을 조합하고, 전용 스타일은 `build(extra_css=...)`로. 두 번 이상 쓰면 `mocks_<도구>.py`로 묶는다(캔바는 이미 있음).
- 한 그림에 같은 번호는 한 번만(점검 스크립트가 경고로 알려준다).
- 확인창·팝업 글자가 줄바꿈되면 폭(width)을 넓힌다. 글은 `word-break:keep-all`이 기본이라 단어 중간에서 끊기지 않는다.
- 그림은 PC·휴대폰 모두 폭 560px로 그린 뒤 확대·축소되므로, 팝업 위치(top/left/right)는 560px 화면 기준으로 정한다.
  오른쪽 끝 메뉴의 팝업은 `right:`로. 팝업이 번호 대상을 가리거나 그림 밖으로 넘치면 점검 스크립트가 알려준다.
- 페이지는 `wrap("".join([section(...), step(...), step(...)]))`처럼 목록으로 이어 붙이면 괄호 실수가 줄어든다.

## 5. 휴대폰·복습
- lessonkit 런타임이 자동 처리: 상단 탭 한 줄 가로 스크롤, 단계 1열, 그림 폭 맞춤 축소 + 탭하면 원래 크기(좌우 스크롤), 표 내부 가로 스크롤, 큰 복사 버튼.
- 편집 실습이 있는 탭은 `wrap(..., pc_note=...)` — 휴대폰에서만 "실습은 PC에서, 휴대폰은 복습용" 안내가 보인다.
- 인쇄(Ctrl+P) 시 모든 탭이 이어서 출력된다.
- 실제 캡처 교체: `shots/<그림ID>.png`를 넣으면 자동 교체(‘모형 보기’ 토글 유지). 캡처 시 개인정보·계정 메일이 보이지 않게.

## 6. 품질 체크리스트 (보내기 전에)
- [ ] 모든 단계에 goal / 번호 순서 / 성공하면 이 있다
- [ ] 글의 번호와 그림의 빨간 번호가 일치한다
- [ ] 메뉴·버튼 이름이 실제 화면과 같다
- [ ] 코드 상자는 실제 파일에서 읽었고, 그 코드는 실행(또는 모의 실행)해 보았다 / 코드 없는 교안은 실습 문구를 스크립트로 점검했다
- [ ] 확인 못 한 화면 이름은 대안을 함께 적고, 보고서에 리허설을 권했다
- [ ] 실습 데이터에 실제 개인정보가 없다
- [ ] 위험한 동작 앞에 시험 단계·확인 단계가 있다
- [ ] `check_lesson.mjs` 문제 없음 + 스크린샷 육안 확인
- [ ] 미리보기 이미지 제목이 자연스럽게 줄바꿈된다
- [ ] 부록에 오류표·되돌리기·개인정보·캡처 목록이 있다
